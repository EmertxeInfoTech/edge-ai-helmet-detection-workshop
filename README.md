# Deploying Vision AI at the Edge — Helmet Detection Workshop

Workshop material for building an automated helmet-violation detection
pipeline from dashcam video and deploying it to run on edge hardware.

Detection finds motorcycles, riders, helmets and licence plates in each
frame; a tracker assigns stable identities; an association stage works out
which rider is on which motorcycle and which head belongs to which rider;
and a temporal decision layer only reports a violation once the evidence is
consistent enough to justify it.

## Run the workshop

Open `workshop/Helmet_Detection_Participant_Colab.ipynb` in Google Colab and
run it top to bottom. It downloads the two assets it needs (about 53 MB) and
requires no local setup.

| Notebook | Purpose |
|---|---|
| `workshop/Helmet_Detection_Participant_Colab.ipynb` | The participant path. Start here. |
| `workshop/Helmet_Detection_Participant_Colab_BACKUP_executed.ipynb` | The same notebook with all outputs, for reference or if a runtime is lost. |
| `workshop/full_pipeline_executed.ipynb` | Full walkthrough of all eight modules, as post-workshop reading. |

## Repository layout

| Path | Contents |
|---|---|
| `final/` | Current pipeline: `src/` modules, `main.ipynb`, model and sample video |
| `notebooks/` | One teaching notebook per pipeline stage |
| `project/pipeline/` | Earlier flat-import version of the same modules |
| `project/webapp/` | FastAPI + SQLite dashboard for reviewing detected violations |
| `*.qmd`, `_quarto.yml` | Quarto site sources |

`final/src/*.py` is generated by the `%%writefile` cells in
`final/main.ipynb`. Edit the notebook cell, not the file, or the next run of
the notebook will overwrite your change.

## The pipeline

| Module | Responsibility |
|---|---|
| `config.py` | Paths, class names and thresholds in one place |
| `detection.py` | Reshapes raw model output into per-class lookup tables |
| `geometry.py` | Reduces boxes to comparable points and overlap scores |
| `association.py` | Matches riders to motorcycles, heads to riders, plates to motorcycles |
| `rm_instance.py` | Accumulates what is known about each rider over time |
| `temporal.py` | Combines many frames into a single verdict |
| `visualization.py` | Renders pipeline state as reviewable images |
| `main.py` | Runs every stage in order across a full video |

Class IDs in `models/best.pt`: `0 rider, 1 motorcycle, 2 helmet, 3 no_helmet,
4 license_plate`.

## Local use

```bash
pip install "ultralytics>=8.3,<9" "onnx>=1.17,<2" "onnxruntime>=1.20,<2" "scipy>=1.13,<2"
cd final && python -m src.main          # writes report and violation snapshots to output/
```

Export for edge deployment:

```python
from ultralytics import YOLO
YOLO("final/models/best.pt").export(format="onnx", imgsz=640, dynamic=False, simplify=True, opset=17)
```

TensorRT `.engine` files are specific to the device and TensorRT version that
built them, so they are generated on the target rather than committed here.
